The big idea

From writing code to expressing intent

For most of computing history, programming was an act of translation: understand the problem, design a solution, then render it in syntax a machine can run. Every step adds friction. That friction is now collapsing.

“Generation is solved. Verification, judgment, and direction are the new craft.”

Why the word matters
Telling a CTO your team is vibe coding the payment system should raise alarm bells. Telling them you practice agentic engineering — AI implementing under human-designed constraints, with tests ensuring correctness — is a completely different conversation. Same tools. Different discipline.

The 20-year arc: autocomplete → autonomy

Each step removed more of the "how" and left more room for the "what." Today an agent can clone a repo, plan a multi-file change, run tests, and open a PR — without you typing a line.

The beating heart
Get the mission → scan the scene → think it through → take action → observe & iterate. The loop is everything. Every agent, however simple or sophisticated, is a variation on it.
The core mental model

Vibe coding → Agentic engineering

It's not a binary — it's a spectrum. The differentiator is not whether you use AI. It's how much structure, verification, and human judgment surround the AI's output. Drag the slider.

Vibe Coding Structured AI-Assisted Agentic Engineering
Right for: Prototypes, scripts, hackathons High risk — acceptable for disposable code
Applied tip
A weekend prototype can be pure vibe coding. A production API handling financial transactions demands agentic engineering. The skill is knowing where to draw the line for each task.

The single biggest differentiator: how outputs get verified

✅ Tests
Verify the deterministic parts. Given this input, the function returns that output. Checked by code.
🎯 Evals
Verify the non-deterministic parts. Did the agent take the right trajectory, choose the right tools, hit the quality bar? Checked by labelled datasets, rubrics & LM judges.

Without both, the practice is always vibe coding — no matter how sophisticated the prompts.

The real skill

Context engineering

Code quality depends less on clever prompts and more on the quality of context you provide. The question shifts from “how do I trick the AI into good code?” to “what would a new teammate need to know — and how do I encode it?”

The six types of context

📋 Instructions
Core role, goals, operational boundaries.
📚 Knowledge
Retrieved docs, diagrams, domain data.
💾 Memory
Short-term session logs + long-term state.
🎴 Examples
Few-shot demos & codebase patterns.
🔧 Tools
Precise definitions of APIs & services.
🛡️ Guardrails
Hard constraints, formats, safety checks.

Agent Skills — progressive disclosure
The most powerful pattern for dynamic context. The unifying mental model

The factory model

The developer's primary output is no longer code — it's the system that produces code. A factory manager doesn't assemble every widget by hand; they design the assembly line and ensure quality control.

👷 Developer designs the system → 🤖 Agents produce the code → ✅ Tests verify the output

The everyday lesson
When an agent does something wrong, the first instinct is to blame the model. More often the failure traces to a missing tool, a vague rule, an absent guardrail, or a context window stuffed with noise. Most agent failures, examined honestly, are configuration failures.
The evolving role

Conductor & Orchestrator

Two modes developers move between fluidly. Toggle to compare — and notice the 80% problem that both must navigate.

Hands-on · Real-time

🎼 The Conductor

Works in real time with an AI pair-programmer. In the IDE, watching code appear, guiding with prompts and corrections — directing every movement.

  • Good for: complex logic, tricky debugging, unfamiliar codebases.
  • Tools: Copilot, Gemini Code Assist, Cursor, Windsurf.
  • Strength: preserves understanding & control.
  • Risk: becomes a bottleneck — directing every keystroke caps the throughput gain.
Async · Multi-agent delegation

🎭 The Orchestrator

Operates at a higher abstraction. Defines goals, assigns them to agents working in parallel/background, checks in periodically, course-corrects.

  • Good for: well-defined tasks, bug fixes, migrations, test generation.
  • Tools: Jules, Copilot agent mode, Cursor background agents, Claude Code.
  • Demands: specification · decomposition · evaluation · system design.

⚠️ The 80% Problem

AI rapidly generates ~80% of a feature. The remaining 20% — edge cases, error handling, integration points, subtle correctness — demands deep contextual knowledge models often lack.

80% — AI generates fast
20% — the hard part

The errors evolved from syntax mistakes to insidious conceptual failures: wrong business-logic assumptions, missed edge cases, architecture that creates long-term debt. They're harder to catch precisely because the code looks right and may even pass basic tests. The pros use AI for what it's good at, and reserve their attention for where it struggles.

Context engineering is a financial lever

The durable takeaways

Three principles that outlast the tools

1
Structure scales, vibes don't.

Vibe coding is valid for exploration and prototypes. For software organizations depend on, the discipline of agentic engineering isn't optional. The gap between “it seems to work” and “it works correctly under all conditions” is where outages and security holes live.

2
AI amplifies your engineering culture.

Teams with strong testing, clear architecture, and healthy review get dramatically more value. AI is a force multiplier — it multiplies both your strengths and your weaknesses.

3
The human role is evolving, not diminishing.

Builders who understand architecture, write precise specs, evaluate output critically, and design feedback loops are more valuable than ever. The skills shift from implementation to judgment.

“Intent is the new interface. The machine handles implementation; the human provides intent, architecture, and judgment.”
