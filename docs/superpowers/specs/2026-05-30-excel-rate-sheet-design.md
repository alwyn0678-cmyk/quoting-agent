# Spec — Serious Excel rate sheet (Q2): real .xlsx → import → Supabase

- **Date:** 2026-05-30
- **Status:** approved design (architecture + parity decision confirmed), pre-implementation
- **Workstream:** Q2 (Excel rate sheet)
- **Scope:** a committed workbook + a pure parser + an importer script + ASSUMPTIONS rows. No change
  to the runtime pricing path, the Phase-0 demo, or any existing golden/eval.

## Why

The repo's only "Excel" today is [excel-rate-card.ts](../../../packages/graph/src/excel-rate-card.ts) —
a **gated** `ExcelOnlineRateEngine` that would *live-read a Graph workbook at price-time* over an
abstract `ExcelWorkbookTransport`. It is parity-proven against a **fake** transport; there is **no real
`.xlsx` file** and no live transport. So a freight manager has nothing to open or edit, and the rate
card lives only as in-code constants ([rate-card.ts](../../../packages/agents/src/rate-card.ts)) + a
SQL seed ([linkport_rate_card.sql](../../../supabase/seed/linkport_rate_card.sql)).

This delivers a **real, serious, multi-lane workbook** as the human-editable source of truth, plus an
**offline importer** that parses it and upserts it into Supabase. The runtime keeps pricing from
Supabase exactly as today.

### Relationship to the existing `ExcelOnlineRateEngine` (kept distinct, untouched)

| | Existing `ExcelOnlineRateEngine` (gated) | Q2 importer (this spec) |
|---|---|---|
| When | At **price-time**, per quote | **Offline**, when the sheet changes |
| Reads | A **Graph** workbook (live, not built) | A **committed `.xlsx`** on disk |
| Writes to | nothing (prices in-memory) | **Supabase** `rate_cards` / `rate_card_lines` |
| Runtime pricing | would bypass Supabase | **unchanged** — still `SupabaseRateCardSource` |
| Status | gated POC, fake transport only | **built here** |

The two share the **same row types** (`RateCardRow`, `RateCardLineRow`) and the same `priceQuote()` /
`assembleRateCard()` core, so neither diverges from the StaticCard (AC-3). This spec does **not** touch
`excel-rate-card.ts` or its test. (Deferred synergy, explicitly out of scope below: the Q2 parser
could later back a *file* `ExcelWorkbookTransport` to make the gated adapter runnable off the real
workbook — not built now.)

## Decisions (locked)

- **Architecture:** Excel → import → Supabase (the editable source of truth is the `.xlsx`; the
  importer keeps Supabase in sync; runtime reads Supabase, unchanged).
- **Real `.xlsx`** via **`exceljs`** (a true binary workbook, not a CSV stand-in).
- **Multi-lane**: the demo lane **plus** two new richer lanes.
- **Parity (the key call):** the demo lane **NLRTM→USNYC is held byte-identical** to the seed /
  ASSUMPTIONS A1–A9 (same 9 lines, same order, same amounts, same version `2026-06-v1`, validity
  `2026-06-30`). Richness goes into the **new** lanes. Rationale: the totals €6,930 / €2,770 /
  €3,520 / €9,890 are baked into the StaticCard, the eval goldens, the dashboard tests, and
  ASSUMPTIONS; re-deriving them buys churn, not signal. Holding parity instead turns the importer
  into a **correctness proof** — "the Excel→rows→card path reproduces the proven card exactly" — the
  same shape of guarantee as AC-3.

## Architecture

```
rates/linkport-rate-sheet.xlsx          <- committed artifact (the deliverable)
   ▲ generated by                          (a freight manager edits THIS)
scripts/gen_rate_sheet.ts (exceljs)      <- typed in-code spec -> writes the .xlsx (reproducible)
                                            keeps the binary honest/reviewable via regeneration

rates/linkport-rate-sheet.xlsx
   │ read by exceljs
   ▼
scripts/import_rate_sheet.ts             <- .xlsx -> RawSheet[] -> parseRateSheet -> upsert Supabase
   │ calls (pure)
   ▼
packages/agents/src/parse-rate-sheet.ts  <- parseRateSheet(sheets) : ParsedCard[]   (UNIT-TESTED CORE)
   │ produces existing types
   ▼
{ card: RateCardRow, lines: RateCardLineRow[] }  -> assembleRateCard -> priceQuote   (AC-3 parity)
```

- **`parseRateSheet` is the deterministic, testable core** and lives in `packages/agents/src/` (root-
  typechecked + vitest-tested). It takes a **neutral cell representation** (`RawSheet[]`) and carries
  **no `exceljs` dependency**, so it is trivially unit-tested on hand-built fixtures. `exceljs` appears
  **only in the two scripts** (which are run via `tsx` and are not typechecked/tested — consistent with
  the existing `scripts/**` convention).
- **No new domain types.** `parseRateSheet` returns the existing `RateCardRow` / `RateCardLineRow`
  from [rate-card-source.ts](../../../packages/agents/src/rate-card-source.ts), grouped as
  `ParsedCard = { card: RateCardRow; lines: RateCardLineRow[] }`.

## Workbook layout (the contract the parser enforces)

`rates/linkport-rate-sheet.xlsx`, **one tab per lane** (tab name = lane code), plus an `About` tab.

Each lane tab (1-indexed rows, column A = label/kind … E = sort):

| Row | A | B | C | D | E |
|----|----|----|----|----|----|
| 1 | `Lane` | `NLRTM-USNYC` | | | |
| 2 | `Version` | `2026-06-v1` | | | |
| 3 | `Valid through` | `2026-06-30` | | | |
| 4 | *(blank)* | | | | |
| 5 | `Kind` | `Code` | `Container` | `Amount (EUR)` | `Sort` |
| 6+ | `base` | `BASE_20GP` | `20GP` | `1800` | `0` |
| … | `surcharge_per_container` | `BAF` | *(blank)* | `320` | `0` |
| … | `per_shipment_fee` | `DOC` | *(blank)* | `65` | `0` |

**Parser rules** (`parseRateSheet`):
1. Skip any tab named `About` / `README` (case-insensitive).
2. Read card meta from the labelled rows: `Lane`→`lane`, `Version`→`version`, `Valid through`→
   `validity_through` (match by the label in column A; values in column B).
3. Find the header row (first row whose column A equals `Kind`). Read each subsequent non-empty row as
   a line until a blank row or end of data.
4. Per line: `kind` ∈ {`base`,`surcharge_per_container`,`per_shipment_fee`} (else **throw** —
   fail-fast, a bad sheet must not silently import); `code` non-empty string; `container_type` =
   trimmed string or **null** when blank; `amount` a finite number ≥ 0; `sort_order` the integer in
   column E.
5. Return one `ParsedCard` per lane tab.

The `About` tab carries one line: *"All figures are INVENTED placeholders — see docs/ASSUMPTIONS.md.
Not real freight rates."* (ties the artifact to the assumptions log).

## Importer behaviour (`scripts/import_rate_sheet.ts`)

- Reads `rates/linkport-rate-sheet.xlsx` with `exceljs`, converts each worksheet to a `RawSheet`
  (`{ name, rows: RawCell[][] }`), calls `parseRateSheet`, then for each `ParsedCard`:
  - **Idempotent by natural key** `(tenant_id, lane, version)`: select the existing `rate_cards` row;
    if found, **update it in place and reuse its `id`**; else insert a new row with a fresh UUID.
    (NLRTM-USNYC therefore updates the seeded card `2222…` rather than duplicating it.)
  - Replace that card's lines: `delete from rate_card_lines where rate_card_id = <id>` then insert the
    parsed lines — the exact pattern the seed already uses (idempotent re-runs).
  - `is_active = true` for all three lanes; `tenant_id` = Linkport `1111…` (a forwarder has many lanes).
- Uses the **service-role** key from env, server-side only (a script) — never bundled to the browser.
- The importer is **not depended on by the runtime** and pulls nothing new into the Phase-0 demo. Per
  the "complete the project, live tests at the end" directive, the **live import run** (against
  Supabase) is **deferred to the end batch**; the *parser parity* is proven hermetically (below).

`package.json` scripts (matching the existing `tsx` convention):
- `"rates:gen": "node --env-file-if-exists=.env --import tsx scripts/gen_rate_sheet.ts"`
- `"rates:import": "node --env-file-if-exists=.env --import tsx scripts/import_rate_sheet.ts"`

`exceljs` is added as a **devDependency** (build/seed tooling, not shipped runtime).

## Testing (every AC = one pass/fail test; all hermetic, no live DB)

- **AC-Q1 (parser, happy path):** `parseRateSheet` on a hand-built `RawSheet[]` for all three lanes
  returns three `ParsedCard`s with the exact lines/order/types/amounts above → unit test.
- **AC-Q2 (PARITY — the headline):** the parsed `NLRTM-USNYC` card, fed through `assembleRateCard` +
  `priceQuote` (the real engine), reproduces the proven totals: **40HC×2 = 6930**, **20GP×1 = 2770**,
  **40HC×1 = 3520**, **40GP×3 = 9890** — and its 9 lines deep-equal the StaticCard's. Proves the
  Excel→card path reproduces the seeded card exactly.
- **AC-Q3 (new lanes price):** the parsed `NLRTM-USLAX` card prices a `45HC×1` (base 3250 + per-
  container surcharges 360+140+225+310+25+200 = 1260 → 4510, + per-shipment 65+45=110 → **4620**),
  proving new container types/codes price with **no engine change** → unit test. (Exact expected value
  pinned in the plan; it is derived, not asserted by re-implementing the sum.)
- **AC-Q4 (fail-fast):** an unknown `kind` (or non-numeric amount) makes `parseRateSheet` **throw** →
  unit test. A malformed sheet must not silently import.
- Tests live in `packages/agents/src/parse-rate-sheet.test.ts`. **Every existing test stays green**
  (nothing it touches is modified).

> Generating the binary `.xlsx` and the live Supabase upsert are **not** pass/fail ACs (one is a build
> artifact verified by regeneration + the parser round-trip; the other is a deferred live test) —
> consistent with the project rule "if it can't be a test, it's not a criterion."
